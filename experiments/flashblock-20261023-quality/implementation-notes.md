## Work scheduling
Use stable groups of four sorted IDs, identical membership/order in dense and s2. Run group0 dense then s2, group1 s2 then dense, alternate thereafter (32 groups; 64 generation calls). Reset seed42 and all request/prefix-cache state before each condition/group. Dynamic completion within group permitted only with tested A/L compaction; never mix between groups. Batch_size=max_active4; max_num_seqs4, TP1, eager. Require each input+4096 <= chosen model limit (at least max prompt length+4096, <=original32768); record capacity and actual maximum. Sequential prefill for memory if needed, identically in both conditions; normal EOS and completion semantics preserved. Same batch membership does not guarantee identical random draws after trajectories diverge; report single-seed exploratory inference accordingly.

Save each group's raw text/token IDs to a new runtime file immediately after completion, with actual committed run SHA, dataset IDs, condition, prompt hashes, output hashes, finish reason, EOS presence, generated length, walltime and resource samples. No overwrite and no re-generation of completed test items. Small metric records may contain numeric gold/prediction and EM; no test question/full solution/raw output in Git. If any failed item remains, report denominator and failure explicitly; don't silently remove it. Do not retry merely wrong/empty answer. Runtime exceptions stop; up to2 committed mechanical repair attempts total if necessary, preserving originals; resume only genuinely unfinished groups with unchanged protocol and disclose mixed SHAs. Extractor errors may not be tuned against test observations.

## Numeric exact-match extractor (must implement and audit BEFORE seeing heldout output)
Use deterministic pure-Python exact rational normalization (Fraction/Decimal, no floating tolerances or symbolic solver). Extract gold suffix after final ####; fail if malformed gold, validated before GPU. For predictions choose last COMPLETE balanced-brace boxed expression (support \\boxed and \\fbox); if a complete last box exists but cannot be normalized numerically, mark extraction failure, do not fall back to an earlier correct box. If no complete box exists, use last numeric literal in output as explicit fallback and record extraction_method. Never consult gold to select candidate. Last-number fallback is permissive and may pick intermediate/truncated reasoning; report results/accuracy by extraction_method and truncation. Do not count units as scaling, '%' is reported numeric value (5% ->5), no fraction-to-percentage inference. Normalize whitespace, thousands comma grouping, optional currency '$', exact signs, decimal/scientific notation, simple a/b, and LaTex \\frac{a}{b}/\\dfrac{a}{b} with simple numeric arguments. Unit wrappers or equations need explicit frozen behavior; safest strict boxed-numeric parse rejects extraneous expression, returns None. No eval(), arbitrary expression calculation or solving equations. Limit candidate length to prevent pathological input.

Author tests without dataset answers: integer, negatives, 1,234 and 1234, 0.50=1/2, .5, scientific1e3, nested frac balanced braces, two boxes choose last, malformed/unclosed box fallback documented, invalid last complete box fails, empty/nonnumeric output fails, zero denominator fails, commas/sign normalization, gold #### suffix, 5% ->5, units rejected, \\boxed{2+3} rejected, currency stripped. Pin script hash and test cases/results before test generation. Use original upstream extraction as optional diagnostic only; our frozen numeric EM is primary. Never use answer-aware selection.
